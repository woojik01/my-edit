# My Edit 0.3 — 범용 코드·텍스트 편집기

## 제품 정의

My Edit는 텍스트로 이루어진 파일을 열고, 만들고, 편집하고, 기기에 저장하는 오프라인 편집기다. 파일 확장자는 입력을 제한하는 조건이 아니다. 문법 강조가 없는 파일도 일반 텍스트로 편집한다.

## 화면 구조

| 영역 | 역할 |
| --- | --- |
| 상단 | 앱 이름, 오프라인 준비 상태, 설치, 업데이트 |
| 파일 목록 | 이 기기에 보관한 파일, 이름 검색, 파일 열기·생성, 길게 누르기 옵션, 백업, 휴지통 |
| 파일 탭 | 여러 파일 전환·닫기, 원본 파일에 저장하지 않은 변경 표시 |
| 편집기 | 전체 너비 편집, 줄 번호, 문법 강조, 접기, 자동 들여쓰기, 찾기·바꾸기 |
| 미리보기 | HTML·SVG 격리 프레임, 안전한 Markdown 렌더링 |
| 상태 표시줄 | 앱 보관 상태, 줄·열, 들여쓰기, 저장 인코딩, BOM, 줄바꿈, 언어 모드 |

모바일에서는 파일 목록을 서랍으로 바꾼다. 편집 공간을 우선하며, 탭과 상태 표시줄은 가로 스크롤을 허용한다. 탭을 닫아도 파일은 작업공간에 남는다.

## 파일과 언어

- 파일 선택기에 확장자·MIME 필터를 적용하지 않는다. 여러 파일 선택과 드래그 앤 드롭을 지원한다.
- 새 파일은 비어 있는 `untitled.txt`에서 시작하며 전체 이름을 직접 정한다. `.env`, `LICENSE`, 임의 확장자도 허용한다.
- Python, JavaScript, TypeScript, JSON, YAML, Markdown, C/C++, C#, Java, Kotlin, Go, Rust, Shell, SQL 등 143개 언어 모드를 번들에 포함한다. 모드 수에는 SQL 방언 등도 포함된다.
- 이름·확장자로 언어를 찾고, 일부 확장자 없는 스크립트는 shebang도 확인한다. 사용자가 일반 텍스트 또는 다른 언어로 바꿀 수 있다.
- 문법 강조는 편집 보조 기능이며 파일을 열 수 있는지와 무관하다. 범용 컴파일러·런타임은 포함하지 않는다. HTML·SVG·Markdown 미리보기는 사용자가 실행하는 선택 기능이다.

## 문자 인코딩과 줄바꿈

| 항목 | 처리 |
| --- | --- |
| UTF-8 | 잘못된 바이트를 대체 문자로 조용히 바꾸지 않고 오류를 표시 |
| UTF-16 LE / BE | BOM으로 감지, 일부 BOM 없는 파일은 널 바이트 패턴으로 감지, 수동 선택 가능 |
| 저장 인코딩 | UTF-8, UTF-16 LE, UTF-16 BE 및 BOM 선택 |
| 레거시 텍스트 | EUC-KR/CP949, Shift JIS, GB18030, Big5, Windows-1252/1251/1250, ISO-8859-2, KOI8-R로 읽기. 미리보기 확인 후 UTF-8로 저장한다고 명시 |
| LF / CRLF / CR | 파일에서 감지하고 출력할 때 유지, 수동 변환 가능 |
| 혼합 줄바꿈 | 편집하지 않으면 원본 줄바꿈 유지. 편집 또는 형식 적용 후 대표 방식으로 통일하고 알림 |
| 바이너리 | 알려진 서명과 제어 문자로 탐지하여 파일 손상 방지 |

UTF-32와 바이너리 형식의 PDF·DOCX·이미지·압축 파일은 편집 대상에 포함하지 않는다. 파일당 입력 한도는 20 MiB, 문법 강조는 1,048,576문자를 넘으면 비활성화한다. 큰 파일의 실제 처리 성능은 기기 메모리에 영향을 받는다.

## 저장과 데이터 보호

1. 편집 내용은 파일별 350ms 지연 후 IndexedDB에 자동 보관한다. **앱에 보관됨**과 **원본 파일 저장**을 구분한다.
2. 새 문서의 첫 저장에서는 폴더를 고르게 하고, 다음 저장부터 선택한 폴더에 현재 파일 이름으로 쓴다. 파일별 디렉터리 핸들과 마지막 저장 시각을 IndexedDB에 보관해 앱을 다시 열어도 저장 위치를 복원한다. **저장 위치 변경**은 다른 폴더를 선택하고 그곳에 파일을 저장한다. 폴더 API가 없는 브라우저는 저장 파일 핸들을 기억하고, 둘 다 없는 브라우저는 다운로드로 대체한다.
3. 파일별 저장 작업은 순서대로 실행하고, 매 저장 시점의 복사본을 기록한다. 파일 전환 중 다른 문서의 내용이 저장되지 않게 한다.
4. 저장 중 추가 편집이 있으면 그 변경은 저장 필요 표시를 유지한다. 로컬 저장 실패는 오류로 표시하고 파일 내보내기는 계속 허용한다.
5. 저장한 파일이 다른 앱에서 수정됐으면 덮어쓰기 전 확인한다. 브라우저가 권한을 다시 요구하면 저장 시 폴더 권한을 요청하고, 거절된 경우 폴더를 다시 선택할 수 있다. 이름을 바꾸면 새 파일 이름으로 저장하며 기존 파일은 그대로 둔다.
6. 편집 시작 및 이후 2분 간격의 변경 시 이전 내용을 복구 지점으로 남기며 파일당 20개까지 보관한다. 복구 전 현재 내용도 기록한다.
7. 휴지통에서 파일을 복원하거나, 확인 뒤 개별 영구 삭제·휴지통 비우기를 할 수 있다. 자동 삭제 기간은 기본 30일, 1~365일로 조절한다. 만료 확인은 앱 실행 중 매시간과 다음 시작 시 처리한다. 영구 삭제는 My Edit의 문서, 복구 지점, 저장 핸들만 없애며 기기에 기록한 원본 파일은 지우지 않는다.
8. 기존 v1 HTML 문서·복구 기록을 DB v3로 이관한다. 기존 문서는 당시 암묵적이던 `.html` 확장자를 이름에 붙이고 내용은 보존한다. 저장 위치를 담는 새 저장소를 추가한다. v1 백업도 읽는다.

## 오프라인·배포

- 실행 자산과 모든 언어 모드를 Service Worker precache에 포함한다. CDN 런타임 요청은 없다.
- 최초 온라인 방문과 캐시 완료가 필요하다. 캐시 완료 뒤에는 파일 생성·읽기·편집·파일 저장·백업을 오프라인으로 사용한다. 브라우저 데이터 삭제는 작업공간 및 캐시 삭제를 의미하므로 백업·외부 파일 저장을 제공한다.
- 새 버전은 사용자에게 적용 버튼을 제공하고 로컬 저장을 완료한 뒤 새로고침한다.
- GitHub Pages는 `main` 브랜치의 루트 정적 파일을 게시한다. 개발 소스는 `app/`, 빌드 결과는 저장소 루트에 둔다.
- 설치 버튼은 브라우저 PWA 설치 기능이다. 별도 Android TWA APK는 이 저장소에 포함하지 않는다.

## 검증 기준

- 임의 확장자·확장자 없는 파일·숨김 파일 생성 및 이름 유지.
- 여러 파일 전환 시 내용·커서·열린 탭의 실행 취소 이력 유지.
- UTF-8/UTF-16, BOM, 한글·이모지, LF/CRLF/CR 저장 바이트 검증.
- 잘못된 UTF-8에서 수동 인코딩 선택, 바이너리 거절.
- DB v1 이관, 백업 왕복, ID 충돌 복원에서 기존 작업 보존.
- DB v3에서 저장 핸들 기록과 영구 삭제의 원자적 정리.
- 자동 삭제 기간별 만료 계산 및 Markdown의 HTML 삽입·위험한 링크 차단.
- 모든 언어 모드 로드 및 빌드 precache 항목 검증.
- 게시된 페이지에서 파일 생성·편집·탭 전환·새로고침 후 복원 확인.
